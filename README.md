# ResumeFit · 国际化算法 / 数据岗位简历机筛适配工具

面向 ML / 算法（搜广推）/ LLM / 多模态 / 数据工程岗位的简历投递自检工具：先模拟海外 ATS 机筛 + HR 初筛 + 用人经理技术评估，给出百分制适配度；不达标时自动生成更贴合 JD 的 **STAR 学术化改写**，并支持 **中英学术化互译**。

## 功能

- **规则引擎（免 AI，秒级）**：关键词覆盖（必备/加分区分）、硬性门槛（年限/学历/英语/论文，按 JD 自动提取）、ATS 可解析性检测（无文字 PDF、双栏表格、图标、日期格式、联系方式缺失等）、STAR 表述质量（量化比例、强动词、口语化弱表述识别，中英文词库）、岗位加分信号（顶会论文、开源、竞赛、线上落地等）。
- **AI 语义评估（可选）**：模拟 HR 6 秒初筛 + 用人经理技术面视角，给出 verdict、级别匹配、能力维度雷达、优势/差距、风险信号、预测面试问题。
- **STAR 改写**：逐条给出原文 → 改写对照、S/T/A/R 拆解、命中的 JD 关键词；**绝不虚构**，缺数据的地方用 `[X%]` 占位符标出，无法如实覆盖的关键词单独列出。
- **学术化中英互译**：技术术语保留英文原词，统一标题/日期格式，可选 STAR 润色。
- **投递表单预测**：根据 JD 预测常见 knockout 问题（工作授权、年限、学历、英语、地点等）。
- **隐私**：上传文件仅在浏览器本地解析，发送前默认对姓名/邮箱/电话/证件号/社交主页 ID/地址/生日做脱敏占位替换；服务端不落盘、不记录请求日志。

## 目录结构

```
server/             纯逻辑模块（评分引擎、Prompt、鉴权与配额），不含前端代码
netlify/functions/  Netlify Functions（/api/verify /api/score /api/llm）
src/                 前端源码（构建输入）
scripts/build.mjs    构建：复制 src -> dist，自托管 PDF.js/Mammoth，混淆 app.js
scripts/dev.mjs      本地开发服务器（无需 Netlify CLI）
```

## 本地运行

```bash
npm install
cp .env.example .env   # 修改 ACCESS_CODES、LLM_API_KEY 等
npm run dev             # http://localhost:8888
```

## 部署到 Netlify

1. `npm run build` 可本地验证构建产物在 `dist/`。
2. 新建 Netlify 站点并连接本仓库（或 `netlify deploy`），构建命令 `npm run build`，发布目录 `dist`，Functions 目录 `netlify/functions`（已写入 `netlify.toml`，一般无需手动改）。
3. 在 Netlify **Site configuration → Environment variables** 中配置（**不要**写入仓库）：
   - `ACCESS_CODES`：`姓名:访问码,姓名2:访问码2`，发给每个人不同的码，泄露时可单独吊销。
   - `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`：你的模型方（可选，不填则仅规则评分可用，接收人仍可在前端"设置"中填自己的 Key 使用 AI 功能）。
   - `DAILY_QUOTA`：每个访问码每日 AI 次数上限。
   - `ALLOWED_ORIGINS`：部署后填你的站点域名（如 `https://xxx.netlify.app`），API 会拒绝其他来源的请求。
   - `DOMAIN_LOCK`：构建时写入前端 JS，锁定只能在该域名下运行（防止被整站下载后在别处托管）。

## 防泄露 / 防白嫖设计

把工具放到 Netlify 这类公开可访问的地址，最大的风险不是“代码被抄”（前端代码本就对浏览器可见），而是：**别人绕过你的入口直接调用你的后端接口 / 偷用你的模型额度 / 拿到你的简历数据**。本项目按下面几层处理：

1. **Prompt 与评分规则只存在服务端**（`server/` 目录，运行在 Netlify Functions 里，浏览器永远拿不到源码），前端只拿到结构化 JSON 结果，无法还原你的 Prompt 工程。
2. **访问码鉴权 + 按人分组额度**：`ACCESS_CODES` 给每个接收人发不同的码，`x-access-code` 校验失败走固定延时（防暴力枚举），AI 调用按码每日限额（`DAILY_QUOTA`），规则评分不占额度。某人的码泄露，直接删掉那一项即可吊销，不影响其他人。
3. **来源校验**：`ALLOWED_ORIGINS` 限制 API 只接受你自己站点发出的请求，别人即使拿到 API 路径也无法用脚本批量调用（除非伪造 Referer/Origin，已足够拦住绝大多数白嫖脚本和搜索引擎探测）。
4. **自带 Key（BYOK）**：接收人也可以在"设置"里填自己的模型 Key，这样消耗的是他自己的额度，不碰你的 Key；服务端限制了可用的 Base URL 白名单，防止被当作任意代理滥用。
5. **前端代码混淆 + 域名锁定**：构建时用 `javascript-obfuscator` 混淆 `app.js`（标识符哈希化、字符串数组加密、控制流扁平化、自我保护），并可选 `DOMAIN_LOCK` 让代码只能在你的域名下运行，脚本被下载到别处会直接失效，提高逆向与白嫖门槛（注意：前端混淆只能提高成本，不能做到绝对防逆向，真正的护城河是上面 1-4 点把"大脑"放在服务端）。
6. **搜索引擎与爬虫屏蔽**：`X-Robots-Tag: noindex, nofollow` + `<meta name="robots">`，不会被搜索引擎收录，降低被陌生人搜到的概率。
7. **安全响应头**：CSP（禁止内联脚本、限制 connect-src 只能访问同源 `/api/*`）、禁止被 iframe 嵌入（`frame-ancestors 'none'`）、`X-Content-Type-Options`、HSTS 等，降低被嵌入钓鱼页或 XSS 的风险。
8. **数据隐私**：简历文件只在浏览器本地解析，不上传原件；默认脱敏姓名/联系方式/证件号/社交主页 ID 后才发往服务端；服务端 Functions 无状态、不写数据库、不记录请求体日志；请求体大小限制约 80KB，防止异常大请求占用资源。

> 如果要更进一步，可以：把访问码换成更长的随机串并定期轮换；给 Netlify 额外加一层如 Cloudflare Access / 简单的 Basic Auth；或把站点设为仅通过一次性链接访问。但对"发给几个朋友内部使用"的场景，以上 8 点已经是较均衡的成本/安全比。

## 重要声明

- 所有改写与翻译均基于**你提供的真实经历**，不会捏造公司、职位、时间、技术栈或指标；缺少数据的地方会用占位符标出，需要你本人核实后再投递。
- AI 语义评估与面试预测仅供参考，不构成录用承诺。
